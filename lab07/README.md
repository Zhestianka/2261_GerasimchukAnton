*Оцените работу следующих фрагментов программ. Какие из них обладают неоднозначным поведением? Почему?*
```
int x=10, y=3;
std::cout << std::min(x=15, x+y);
```
```
int x=10, y=3;
x=15, y+=x, x+=y;
```
```
int x=10, y=9;
if (x>y++ && y++>9)
  cout << "yes" << endl;

```

---

## Ответ

- 1

![1](https://github.com/Zhestianka/ProgLang/blob/main/lab07/01/2026-10-30%2012.38.27.jpg)

Здесь неоднозначно, потому что порядок вычисления аргументов функции std::min не задан. Первый аргумент x = 15 меняет x. Второй аргумент x + y читает x. Возможны два варианта:

1) Сначала выполнится x = 15. Тогда x + y = 15 + 3 = 18, и std::min(15, 18) даст 15.
   
2) Сначала выполнится x + y. Тогда x + y = 10 + 3 = 13, потом x станет 15, и std::min(15, 13) даст 13.

Итог зависит от порядка вычисления аргументов.

- 2

![2](https://github.com/Zhestianka/ProgLang/blob/main/lab07/01/2026-10-30%2012.38.34.jpg)

Здесь запятые — это оператор запятая. Он гарантирует порядок слева направо:

1) x = 15 → x = 15

2) y += x = 3 + 15 = 18

3) x += y = 15 + 18 = 33

Итог: x = 33, y = 18. Поведение однозначное.

- 3

![3](https://github.com/Zhestianka/ProgLang/blob/main/lab07/01/2026-10-30%2012.38.41.jpg)

Оператор && вычисляется слева направо и с коротким замыканием.

1) x > y++: 10 > 9 — истина, после этого y становится 10.

### Задание 2 **(2)**
*Как записать следующие строки программы на С++ в виде одного
выражения? Приведите несколько способов, в том числе с использованием операторов инкремента.*
*Проверьте работу написанных программ*
```
x=x+1;
z=z+2*x+3*y;
y=y+1;
```
*Тексты программ разместите в папке с номером задания*

---

## Ответ

1) Почти как в исходнике, но через запятую

x = x + 1, z = z + 2 * x + 3 * y, y = y + 1;

2) Через +=

x += 1, z += 2 * x + 3 * y, y += 1;

3) Через ++ и запятую

x++, z += 2 * x + 3 * y, y++;

4) Без запятой, в одном выражении

z += 2 * ++x + 3 * y++;

Во всех четыре вариантах сначала увеличивается x, затем z пересчитывается с уже увеличенным x и прежним y, после чего увеличивается y.

### Задание 3 **(2)**
*Рассмотрите следующий фрагмент программы. Он заполняет вектор из 10 элементов единицами.*
```
std::vector<int> x(10);
for (int i = 0; i < 10;)
   x[i++] = 1;
```
*Перепишите ее так, чтобы в третьей строке использовался префиксный инкремент, но результат ее работы не изменился.*
```
std::vector<int> x(10);
for (...)
   x[++i]=1;
```

---

## Ответ 

++i — префиксный инкремент: сначала увеличивает i, потом подставляет новое значение в индекс. Поэтому если начать с i = -1, то первый ++i даст 0, и запись будет в x[0]. Дальше индексы пойдут 0, 1, 2, ..., 9. После записи в x[9] переменная i станет равна 9, условие i < 9 станет ложным, цикл закончится. Если начать с i = 0, то первый ++i даст 1, и запись начнётся с x[1], а в конце будет попытка записать в x[10] — это выход за границы вектора.

### Задание 4 **(2)**

*Почему присваивание* ```(++x)=y``` *является синтаксически правильным, а*
```(x++)=y``` - *нет? Запишите текст сообщения об ошибке, переведите и объясните его.*

---

## Ответ 

Оба выражения синтаксически корректны. Разница семантическая: слева от = должно быть изменяемое lvalue.

++x увеличивает x и возвращает сам x как lvalue (++x)=y можно.

x++ увеличивает x, но возвращает старую копию как rvalue (x++)=y нельзя: временной копии нельзя присвоить значение.

компилятор говорит, что (x++) нельзя использовать как левую часть =, потому что x++ даёт временное значение, а не объект, в который можно записать y.

### Задание 5 **(2)**

*Программисты на Python для обмена значений двух переменных часто пишут строку*
```
a,b = b,a
```
*Проверьте, будет ли аналогичная строка на С++ (с точкой с запятой в конце) являться синтаксически
правильной? Будет ли она обменивать значения переменных? Как в языке С++ вычисляется это выражение?*

---

## Ответ

В C++ синтаксически корректна, но обмена не делает. C++ разбирает её как a, (b = b), a. Потому что запятая в C++ — оператор с низким приоритетом, а = выполняется раньше.a вычисляется и отбрасывается, затем b = b, затем снова a. Значения не меняются.

### Задание 6 **(2)**

*Проверьте работу следующего фрагмента программы*
```
  std::string s;
  for (int i=0; i<1000000; i++)
     s += 'a';
  std::cout << s.size();
```
*Измените третью строку на*
```
s=s+'a';
```
*Изменится ли что-нибудь в ее работе? Объясните результат.*

---

## Ответ 

Оба варианта работают одинаково

- s += 'a' — символ добавляется в конец той же строки. Память иногда перевыделяется, но с запасом, поэтому в среднем это эффективно: суммарно примерно O(n).

- s = s + 'a' — сначала создаётся новая строка s + 'a', в неё копируется всё текущее содержимое s, потом результат присваивается обратно. На каждой итерации копируется вся уже накопленная строка, поэтому суммарно получается примерно O(n^2). На миллионе итераций это заметно медленнее.

### Задание 7 **(2)**

*Как работает следующая программа? Как зависит результат от исходного значения?*
```
int x;
std::cin >> x;
x-->0 && x-->0 && x-->0 && x-->0 && x-->0;
std::cout << x;
```

---

## Ответ 

x-->0 — это (x--) > 0: сначала сравнивается текущее значение x с нулём, потом x уменьшается на 1. Уменьшение происходит всегда, даже если сравнение ложно.

&& проверяет слева направо и останавливается после первого false. Поэтому выполняются не все пять x-->0, а только до первой ложной проверки.

### Задание 1 **(2)**

*Найдите и объясните примеры "коварных" ошибок программистов на С++, связанных с вычислением выражений. 
Каждый пример оценивается в два балла. Примеры из лекции или из заданий не засчитываются.*

---
## Ответ

## Пример 1.

```cpp
int a = -1;
unsigned int b = 1;
if (a < b) {
    std::cout << "a < b";
} else {
    std::cout << "a >= b";
}
```
при сравнении `int` и `unsigned int` компилятор неявно преобразует `a` к беззнаковому типу. Число `-1` превращается в очень большое положительное (например, `4294967295`). Поэтому условие `a < b` оказывается ложным, хотя интуитивно `-1 < 1`.

```cpp
if (a < static_cast<int>(b))
```

---

## Пример 2

```cpp
double x = 0.1 + 0.2;
if (x == 0.3) {
    std::cout << "Равно";
} else {
    std::cout << "Не равно";
}
```

числа с плавающей точкой хранятся приближённо. Сумма `0.1 + 0.2` может дать `0.30000000000000004`, что не равно точно `0.3`. Условие окажется ложным.

```cpp
if (std::abs(x - 0.3) < 1e-9)
```

---

## Пример 3

```cpp
int a = 1000000;
long long b = a * a;
std::cout << b;
```
умножение `a * a` выполняется в типе `int` (так как оба операнда `int`), и результат переполняет диапазон `int`. Это неопределённое поведение. Только после умножения результат приводится к `long long`, но это уже поздно.

```cpp
long long b = static_cast<long long>(a) * a;
```

---

## Пример 4

```cpp
int x = 0;
if (!x == 5) {
    std::cout << "Условие истинно";
} else {
    std::cout << "Условие ложно";
}
```
оператор `!` имеет более высокий приоритет, чем `==`. Сначала вычисляется `!x` (для `x = 0` это `1`), затем `1 == 5` — ложь. В результате выводится «Условие ложно».
